# 拾句英语 · 精细讲解视频 制作流程

从「给一个原片视频」到「成片 + 封面 + 文案 + PDF 学习资料」的完整流程。
产物落在 `精细讲解视频/`，工具在 `精细讲解视频/_tools/`。

> **规格与参数（配色 / 字体 / 音色 / 画布锚点 / 内容规则）以工作区技能为准**：
> `__WORKSPACE__/.trae/skills/xiaohongshu-explain-video/SKILL.md`
> （「小红书精讲视频」技能）。本文件负责**操作步骤**，技能负责**锁定参数**，两边不要各写一套。

```
精细讲解视频/
├── 01_<选题>/              一个选题一个文件夹（成片及其配套都在里面）
│   ├── <选题>.mp4          成片（1080×1920）
│   ├── <选题>.srt          讲解字幕（第 10 步产出，原声段不打）
│   ├── <选题>_封面.png     封面（1080×1440）
│   ├── <选题>_说明.json    剪辑说明（切点/音色/配色/参数）
│   └── <选题>_精讲笔记.pdf 学习资料（第 9 步产出）
├── 小红书发帖文案.md        跨选题的发布文案（留在顶层）
├── .env.elevenlabs         Voice ID / API Key（渲染器从这里读，勿放进子文件夹）
├── _废弃/                  旧成片，保留备查
└── _tools/
│   ├── build.py            渲染器：卡片 + 旁白 + 合成（改 SPECS 加新视频）
│   ├── auto_build.py       队列自动出片：版面自检 → 渲染 → 校验 → 封面 → PDF → SRT（`--wait N` 可守着队列等创意部分备好）
│   ├── 队列.json            auto_build 的待做清单（prefix / 选题名 / 表达详解 md / 标题副标）
    ├── covers.py           封面生成
    ├── transcribe.py       长素材整体转写（faster-whisper，出 SRT + 词级 JSON）
    ├── fix_srt.py          按修正表改 SRT 里的错词
    ├── split_srt.py        按话题边界把整份 SRT 切成若干段
    ├── handout.py          把「表达详解」md 排成 A4 PDF 学习资料（Chrome 无头打印）
    ├── make_srt.py         从成片反推字幕：文本取脚本旁白原文，时间轴用 ASR 词级时间戳对齐
    ├── 流程.md              本文件
    └── work/<选题>/        中间产物：卡片 PNG、每段 mp4、旁白缓存
```

> 顶层目录 2026-09 起带 `01_`/`02_` 序号前缀，脚本统一用 `build.topic_dir('<选题>')` 解析
> （先找「序号_选题名」，找不到再退回不带前缀的名字），不要在脚本里硬拼 `SERIES/<选题>`。

## 一、流程总览

| # | 阶段 | 关键动作 | 产出 |
|---|---|---|---|
| 0 | **素材准备** | 收原片 / 高清版 / 字幕；判断素材长短 | — |
| 0+ | **长素材建库**（>30 分钟才做） | 转写校对 → 按话题切分 → 逐段提表述 → 逐段写详解 | `分段-重点表述.md`、`表达详解/` |
| 1 | 选题拆解 | 挑出这段的重点表达，逐个起情绪名、写迁移例句 | 分镜表 |
| 2 | 定位切点 | 逐词时间戳 → 截片段 → 二次识别复核 | 干净的原声区间 |
| 3 | 登记内容 | 往 `build.py` 的 `SPECS` 加一条 → **⑤ 扫规格表确认** | SPECS 条目 + 规格确认 |
| 4 | 版面自检 | 只渲染卡片 PNG 查五件事（**先别花 TTS 钱**） | 自检通过 |
| 5 | 生成旁白 + 渲染 | TTS + 卡片 + 合成 + concat | `<选题>.mp4`、`_说明.json` |
| 6 | 校验成片 | 尺寸 / 原声完整 / 停顿 / 留白 / 配色 | 校验记录 |
| 7 | 封面 | 人脸聚类找帧 → 排 3:4 封面 | `<选题>_封面.png` |
| 8 | 小红书文案 | 标题 / 正文 / 标签，控字数、去符号 | 文案段落 |
| 9 | **精讲笔记 PDF** | 把讲过的表达排成 A4 学习资料 | `<选题>_精讲笔记.pdf` |
| 10 | **导出讲解字幕** | 从成片反推 SRT（文本取脚本旁白，时间轴走 ASR 对齐） | `<选题>.srt` |

**三条约定**
- 一个讲解视频**详尽讲解这段里的重点表达**（逐句讲透，不设 2–3 个的数量上限），配一个**情绪钩子**（不是语法名）。
- 成片输出目录 = `SERIES/<选题>/`（`build.py`、`covers.py`、`make_srt.py` 都走 `topic_dir()` 落盘；
  2026-09 起顶层目录带 `01_`/`02_` 序号前缀，解析由 `topic_dir()` 统一处理）。
- 顶层只放跨选题的文件（发布文案、密钥）和 `_tools`、`_废弃`。

**分支怎么走**
- 素材 **≤ 10 分钟**：跳过 0+，直接从第 1 步走到第 10 步。
- 素材 **> 30 分钟**：先做 0+（把素材变成可检索的表述库），之后每做一条视频都从库里挑句型，
  仍然走第 1→10 步，只是第 1 步变成"从库里选"。
- **第 10 步每条都要做**（2026-09 起）：成片交付时 SRT 一起交付，不要等有人来要。

## 二、前置：素材准备

### 第 0 步 · 素材准备

| 素材 | 用途 | 备注 |
|---|---|---|
| 原片视频 | 画中画的访谈原声 | **优先用高清版**。低清（如 640×360）放大到 810 宽会发虚 |
| 高清版（如有） | 同上 | 换素材前必须复核时间轴是否一致（见第 2 步第 4 点） |
| 字幕 / 逐字稿 | 找句式、定切点 | 机器翻译的字幕不要直接用，中文要重译 |

### 第 0+ 步 · 长素材（30 分钟以上）先建「分段 + 表述库」

一条 1 小时的访谈能出几十条视频。**不要一上来就选题**，先把素材变成可检索的表述库。
前半（转写 / 校对 / 切分）做完一次就够，后半（表达详解）按章节逐步推进。

**① 整体转写**：`transcribe.py`。先用 `small` 跑通（约 4x 实时），再用 `medium` 跑一遍
（约 1.7x 实时）做交叉校对，两版都留着。

**② 词级比对**：把两版按词对齐算相似度（同类素材一般 >97%），**逐处看差异**——差异处就是可疑错词。
注意**两个模型各有各的错**：实测 medium 整体更准（Dior、slid the rail、male-dominated sport 都对），
但它会把 mines 听成 minds。所以必须按位置逐条判断，不能盲信某一版。

**③ 修正 SRT**：把确认的错词写进修正表（格式 `时间 | 原片段 | 改成`），用 `fix_srt.py` 套到更准的那一版，
输出 `*.修正.srt`。**存疑的项写进修正表的注释区，留待人工听校——不要凭猜测改原文**。

**④ 按话题切分**：人工列话题边界（一行一个 `mm:ss 标题`），用 `split_srt.py` 切成 N 段，
每段输出 `.srt` + `.txt`（纯文本便于喂给子代理）。一段 2–6 分钟最合适。

**⑤ 逐段提重点表述**（可并行）：每段目标 **12–20 条**，字段 = 表达/句型、原句、时间点、说话人、
教学点、★（该段最适合单独做视频的 3–5 条）。量大的时候**用子代理并行**，每个负责约 3 段；
**先跟子代理约定死输出格式**（markdown 表格），否则汇总时要返工。

**⑥ 汇总成 `<素材>-分段重点表述.md`**，作为后续的选题库。

**⑦ 逐段做「表达详解」（穷尽式，二次加工）**：表述库是"选出值得教的"，表达详解是"把每段讲透"。
一段 1–2 分钟的内容常常能挖出 40–60 条。格式固定：

```
**N. `表达`** ｜ 时间
原句：…（英文原句）
意思：…（中文）
用法：…（搭配 / 易错 / 语域）
迁移：…（可搬到学习者自己场景的例句）
```

按类别分组（套话 / 表达赞美 / 回应赞美 / 口语标记 / 高频搭配 / 句型结构 / 语用小贴士），
最后附「本段最适合单独做视频的 5–6 条」。
**这份文档同时是视频素材源、PDF 学习资料的数据源、以及产品练习内容的素材源。**

**原则**：素材越大，越要先建库再动手；否则每做一条都要重读全文。

## 三、主线九步

### 第 1 步 · 选题拆解

1. 通读原片，挑「结构清晰 + 能迁移到学习者自己身上」的句式。
   例：`have an opportunity to…`、`The worst that can happen is…`、`not … anymore`、`have room to grow`。
2. 给每条选题起一个**情绪名**（不是语法名）：勇敢开口（怕说错不敢开口）／继续成长（总觉得自己还不够好）。
3. 用**原片真实英文原句**（可微调标点），配自然中文翻译。
4. 写**迁移例句**：把原句里的宾语/主语换成学习者的场景。
   > 原句：When you have an opportunity to try something, take it.
   > 迁移：When you have an opportunity to **speak English**, take it.
5. **迁移例句一定是原创，不是访谈原话，但别把这句话说出来**（2026-09 起改口径）：
   旁白用**邀请式**递句子——「你也可以试着这样说……」「换成你自己的情况，可以这样说……」；
   **不写「这是我们的原创练习句」「这句不是她说的」**（听着像免责声明，一手把观众拉出学习状态）。
   小红书文案同理，不写免责口吻的句子；需要区分时自然带一句
   （例：「她原话是这几句；练习句照着这个结构换成你自己的版本」）。
6. **旁白/卡面写「这句有什么用」，不写「这句多值钱」**（2026-09 起）：`最值钱的`、`金句`、`全是宝`、
   `干货`、`封神`、`天花板`、`保姆级`、`狠狠` 这类词是在**代替说明**，听着热闹、学员拿不到信息，
   而且一眼看出不是人写的。换成「什么场合、对谁、起什么作用」。
   > 自查：把这句评价删掉，句子还成立吗？删掉后信息量为零，就是空话。
   > × 本片最值钱的一句 → ✓ 谈自我认知最完整的一句，面试和自我介绍都能用
   > × 这一条是本片最值钱的隐喻 → ✓ lens 是镜头，也是看问题的角度，谈学习路径时能用
   > × 主持人追问的这一句，全是宝 → ✓ 他这两问，一个问兴趣、一个问方向，都能直接搬

**产出**：分镜表，每张卡片一行：标题 / 屏幕文字 / 旁白 / 原声区间。

### 第 2 步 · 定位切点（最影响质量的一步）

**长素材（10 分钟以上）** 用 `_tools/transcribe.py` 整体过一遍，拿 SRT（给人看/挑选题）
和 JSON（词级时间戳，给切点用）：

```bash
cd <素材所在目录>          # 输出写在素材旁边
/opt/homebrew/bin/python3 <…>/_tools/transcribe.py <媒体文件> small
```

faster-whisper 比 openai-whisper 快很多；`small` 约 4.2x 实时、`medium` 约 1.7x 实时。
长素材一定要带 `condition_on_previous_text=False`，否则容易陷入重复循环。

**短素材（5 分钟以内）** 直接用 whisper CLI：

```bash
ffmpeg -y -v error -i <原片> -ac 1 -ar 16000 source.wav
whisper source.wav --model small --language en --word_timestamps True \
        --output_format json --output_dir . --fp16 False
```

拿到时间戳后，四件事：

1. 从 JSON 里取目标句的**逐词**起止时间。
2. **粗定切点 → 截出候选片段 → 二次识别复核**。复核文本必须和目标句逐字一致；
   如果多出前一个词的尾音（如 "and" / "that"），就往后挪 0.1–0.2 秒重试。
3. 找不到干净边界时，用 **RMS 包络**找词间静音谷（10ms 窗口）：
   ```bash
   ffmpeg -y -v error -ss <起> -to <止> -i <原片> -ac 1 -ar 16000 f.wav
   ```
   逐 10ms 打印 RMS，取相邻两词之间的最低点作切点；宁可留 50ms 静音，也别从词中间切。
4. **换素材（低清→高清）后必须重跑本步**，确认时间轴没变。

> 这一步别偷懒。实测代价：一次没逐词复核，就有 3 处切点不干净（从词中间切入、切在半句、多带一句），
> 只能重渲一遍。

### 第 3 步 · 登记内容（`_tools/build.py` 的 `SPECS`）

做五件事：**① 加 SPEC 条目 → ② 看卡片形态 → ③ 对版面锚点 → ④ 看旁白参数 → ⑤ 出片前扫规格表**。
第 ⑤ 条是出片前的最后一道闸，**别跳**（2026-09 加，理由见下）。

**① 加一条选题** = 往 `SPECS` 加一个字典：

```python
'谷爱凌_XXX': {
    'src': '…/另一支素材.mp4',        # 可选；不写就用 DEFAULT_SRC
    # 新片：style / fonts / voice / model / voice_settings / speed / foot 全是默认值，一个字都不用写
    #      （默认 = v2 深色 · 宋体 · eleven_v3 · style 0.4 · 1.2 倍速 · 无页脚）
    # 老片（要原样复现）才写这几项：
    'style': 'v1',                    # 2026-09 前的浅色版
    'fonts': 'heiti',                 # 黑体
    'model': LEGACY_MODEL,            # eleven_multilingual_v2
    'voice_settings': LEGACY_VOICE_SETTINGS,   # style 0 + 带 speed
    'speed': 1.0,                     # 原速
    'foot': True,                     # 保留底部分隔线与页脚
    'url': True,                      # 页脚里放官网链接
    # 派生版才写这几项：
    'speed_src': 1.2,                 # 访谈原声的倍速（默认 1.0，原声是学习材料，一般不动）
    'out_dir': '谷爱凌_XXX',           # 成片落回主片目录，不另建文件夹
    'work': '谷爱凌_XXX',              # 复用主片的中间产物目录（见「派生版」小节）
    'cards': [
        dict(n='01', title='封面大标题',
             lines=[(990, '屏幕文字', 60, 'green', False)],   # (y, 文字, 字号, 颜色角色, 是否英文)
                                                              # 颜色只写 'fg'/'green'/'green2'/'mute'
             speech=[('zh', '中文旁白'), ('en', 'English line.')],
             source=(88.0, None)),                            # 原声区间；None = 跟旁白等长
        dict(n='02', title='先听原句 / 01',
             lines=[...], source=(70.03, 71.10)),             # 只有原声，无旁白
    ],
}
```

**② 一张卡片的三种形态**（`render()` 自动判断）

| 有旁白 | 有原声 | 行为 |
|---|---|---|
| ✓ | ✗ | 卡片 + 旁白 |
| ✗ | ✓ | 卡片 + 画中画播原声 |
| ✓ | ✓ | **先讲解、再听原声**：切成两段——讲解段用原声起点的**定格帧**占住画中画位置，原声段再把视频放上去，视觉无跳变 |

**③ 版面锚点（1080×1920，别随意改）**

| 元素 | 位置 |
|---|---|
| 品牌块 | (72,190)–(272,250) |
| 标题 | y=318（超过可用宽度会**自动缩号**，62→34） |
| 分隔线 | **只有顶部 y=424**（底部 y=1408 已取消） |
| 原片画中画 | 810×456 @ (135,470) |
| 卡片正文 | 无原声 470–1470；有原声 950 起，行位 950/1030/1110/1190/1270/1350/1410，最多 7 行 |
| 页脚品牌条 | **无**（2026-09 起整条不画） |

上下留白：**上 190px、下 418px**——避开小红书顶部状态栏和底部文案/按钮区（y=1503 是安全线）。

> ⚠️ **新片不画页脚**（2026-09 起）：原先页脚放 `https://shijuenglish.cn/`，实测被小红书判成引流**限流**。
> 现在连底部分隔线一起去掉，下半区全给正文——正文下沿 1380 → **1470**，有原声的卡 5 行 → 7 行。
> **最后一行排 1410**：行位的 y 是文字框顶，墨迹还要往下延伸约 1.25×字号（44px 的行排 1410 → 墨迹到 1470；
> 排 1425 就溢到 1480 了）。`build.py` 默认 `SHOW_FOOT = False`，老片在 SPEC 写 `'foot': True` 锁住原样。

**④ 旁白**：中文原速，英文 `atempo=0.8`（`EN_SLOW` 常量）；中英分段之间停 0.22s。整体默认 1.2 倍速（见技能文档）。

**⑤ 出片前扫一眼规格表（★ 必做）**

30 秒，挡的是「漏写字段 → 悄悄用了默认值 → 音色/字体跟前后几条不是一路」这类事故。实际踩过一次：
05 女性气质只写了 `src` + `cards`，默认值当时还是旧规格（黑体 + `eleven_multilingual_v2` + style 0），
那条片子就用上一代音色发出来了，**是用户听出来的**。

```bash
cd "__DATA_ROOT__/小红书发帖-拾句英语/精细讲解视频"
/opt/homebrew/bin/python3 - <<'PY'
import sys; sys.path.insert(0,'_tools'); sys.argv=['x']
import build as B
for k, s in B.SPECS.items():
    vs = s.get('voice_settings', B.DEFAULT_VOICE_SETTINGS)
    has = (B.topic_dir(k)/f'{k}.mp4').exists()
    print(f"{'有片' if has else '无片':<3} {k:28s} {s.get('fonts',B.DEFAULT_FONTS):>5} "
          f"{s.get('model',B.DEFAULT_MODEL):>22} style={vs.get('style')} "
          f"speed={s.get('speed',B.DEFAULT_SPEED)} foot={s.get('foot',False)}")
PY
```

**怎么看**：

1. 先找到**你要渲的那条**（刚加进去、显示「无片」的那行）——它的 fonts / model / style / speed
   必须跟**最近一条「有片」的逐项一致**。不一样就是漏写字段、或者有意换了规格。
2. 老片（2026-09 前的）反过来，应当是 `heiti` + `eleven_multilingual_v2` + `style=0.0` + `speed=1.0` + `foot=True`。
   注意**它们也会显示「无片」**——因为 mp4 已归档到 `废弃/`，不在选题目录里了，忽略即可。
3. 派生版（倍速 / 试听 / 字幕）允许 `speed` 不同，其余仍要对齐。
4. 对完再进第 4 步。**发现不一致就回去改 SPEC，别靠「反正能出片」放过去。**

> 默认值已经在 2026-09 改成新规格（v2 深色 · 宋体 · `eleven_v3` · style 0.4 · 1.2 倍速 · 无页脚），
> 所以新片「什么都不写」就是对的做法；这张表看的就是**有没有意外偏离**。

### 第 5 步 · 生成旁白 + 渲染

```bash
cd /Volumes/.../精细讲解视频          # 工作目录必须在目标盘内（沙箱限制）
/opt/homebrew/bin/python3 _tools/build.py <选题>
```

脚本做的事：ElevenLabs TTS（逐段、sha256 缓存）→ 每段 `loudnorm` + 变速 → PIL 出卡片 →
ffmpeg 合成每段 → concat 成片 → 写 `_说明.json`。

- 音色：`__VOICE_ID__`。**新片**用模型 `eleven_v3` + `stability 0.45 / style 0.4`
  （v3 不支持 speed 参数）；2026-09 前的旧片是 `eleven_multilingual_v2` + `style 0`。
- 改文案后重跑不会重复扣费（缓存按 `文本+音色+模型+参数` 的 sha256 命中）
- 一条 16 分钟的片子旁白约 4900 字、约 150 次 TTS 调用，渲染 5–10 分钟，属正常

**加字幕**（给中文母语用户：边听边读）——SPEC 里写 `subs=True`：

| 项 | 做法 | 为什么 |
|---|---|---|
| 覆盖范围 | 只覆盖讲解旁白，原声片段不打 | 字幕要跟旁白一一对应；原声要听懂得另外配英文字幕 |
| 样式 | 白字 `#FFFFFF` + 1px 黑描边，字号 40，单行 | 描边是为了压在访谈画面上也看得清 |
| 位置 | 画面中下方，SPEC 用 `sub_cy` 定高度（本片 1282） | 放正中间会挡住访谈画面里说话人的表情和手势；贴到底部分隔线又只剩二十几像素 |
| 断行 | 按像素宽度切，中文只认标点、英文再加空格 | 认空格的话「2 分 5 秒」会被切成「分 5」这种碎条 |
| 计时 | 没有词级时间戳，按字数比例摊到该句实际时长 | 每段末条挂到段尾，段与段用 1ms 错开，不然字幕会在半句之间闪断 |

**先定 `sub_cy`**：各卡文字位置不一样，字幕高度不能拍脑袋。下面这段列出「整条空带」
（上下各留 6px），挑一条高度 ≥45px 的填进 SPEC：

```bash
cd _tools && /opt/homebrew/bin/python3 - <<'PY'
import sys; sys.path.insert(0,'.')
import build as B
from PIL import ImageFont
name='<选题>'; lo, hi, pad = 1000, 1408, 6      # 只看内容区下半段
occ=[0]*1920
for c in B.SPECS[name]['cards']:
    for y,s,size,col,en in c['lines']:
        b=ImageFont.truetype(B.EN if en else B.CN, size).getbbox(s)
        for yy in range(y+b[1]-pad, y+b[3]+pad): occ[yy]+=1
start=None
for y in range(lo,hi+1):
    if occ[y]==0 and start is None: start=y
    if (occ[y] or y==hi) and start is not None:
        if y-start>=45: print('空带 y %d-%d，建议 sub_cy=%d'%(start,y-1,(start+y-1)//2))
        start=None
PY
```

- 字幕是**窄带透明 PNG 逐条叠**（80px 高），不是整张 1080×1920，也不走 libass——
  一是省内存，二是能直接用卡片同款字体和 PIL 的描边，不受 fontconfig 影响。
- 叠加顺序必须是**卡面 → 画中画 → 字幕**，先画在卡上会被画中画盖住。
- **派生版（加字幕 / 换音色试听）要把 `work` 指到主片目录**，复用同一条旁白音轨：
  TTS 不保证同文本同结果，重合成会让「只多了字幕」的对照组失真。

### 第 6 步 · 校验成片

```bash

ffprobe -v error -select_streams v:0 -show_entries stream=width,height,sample_aspect_ratio \

ffmpeg -hide_banner -i <成片> -af silencedetect=noise=-45dB:d=2.5 -f null - 2>&1 | grep silence_start

# 留白与配色（视频帧有色偏，比对时给 ±14 容差）

# 字幕（带字幕版）：和有字幕前的同一帧比，差异应**只落在 y 876–916 这条带**里；
# 原声段那几处应当完全没有差异
```

五项都要过：**尺寸 / 原声完整 / 停顿 / 留白 / 配色**。
**原声段要逐段抽查**——这是唯一能发现切点问题的地方。

> ⚠️ **抽查要带余量**：按「`_说明.json` 段时长累加」算出的位置，跟成片真实时间轴有 **0.25–0.3 秒**的漂移
> （每段末尾那点静音被算进去了，越往后累得越多）。直接按累加值取整段，会切掉片段最后半个音节，

> 2026-09 实测：`08` 卡 30 的 `potential` 就是这么被判成「被截断」的——
> 把成片窗口放宽 0.5 秒转写就完整，再用滑窗互相关与源片比对，**相关系数 0.94**，确认是同一段音频、内容无损。

### 第 7 步 · 封面（`_tools/covers.py`）

看不到画面时，靠检测找人物镜头：

1. 1fps 抽帧 + Haar 正脸检测（`cv2.data.haarcascades`），再叠眼睛检测筛掉闭眼/侧脸
2. 用 64×64 灰度归一化人脸特征做 **k-means 聚类**，按时间分布分出不同人物
3. 拿一张**已知人物的参考图**（如平台官方封面）比对各簇中心，距离最近的那簇就是目标人物
4. 在目标簇里按「清晰度（Laplacian 方差）+ 亮度 + 能识别到双眼」排序选帧
5. `_tools/候选帧.png` 是候选帧对照图，方便人工换帧

封面版式（1080×1440，3:4）：上半 760px 人像（按人脸中心裁切，脸放在上三分之一），
中间 8px 品牌绿分隔条，下半品牌文字区（品牌块 / 两行大字 / 副标题 / 页脚）。

**写完文案先量宽度**（`covers.py` 不会自动缩号，超了就直接画到画布外）：
可用宽度 `RIGHT-SIDE = 936px`，两行大字是 **132px**（纯文字版）/ **108px**（人像版），
即纯文字版每行**最多 7 个全角字**（含「」这类标点），人像版最多 8 个。
实测踩过一次：人像版 8 字正好，纯文字版同一句就超了 120px。

### 第 8 步 · 小红书文案

按 `小红书发帖文案.md` 的体例，每条视频一份：

- **标题**：主标题 ≤20 字（小红书标题字段上限），备选标题放「发布参考」里
- **正文**：可直接复制。结构 = 具体困境 → 原声金句（EN/CN）→ 句型拆解 → 迁移例句 → 一句收束
- **句型 + 原创练习句**：供置顶评论用
- **话题标签**：8–10 个，**算在正文字数里**
- **发布建议**：封面文件、字数、**唯一动作**、互动引导、置顶评论、练习入口、发布时间
- **必须标注**：练习例句是原创，不是人物原话
- 每篇**只给一个动作**，不要同时要求关注、加群、下载、买课

**两条硬约束**

1. **长度**：正文 + 话题标签合计 **≤800 字符**（小红书上限 1000，留出发布时微调的余量）。写完必须数字数：
   ```bash
   /opt/homebrew/bin/python3 - <<'PY'
   src=open('/Volumes/.../精细讲解视频/小红书发帖文案.md').read()
   for s in src.split('\n## ')[1:]:
       name=s.split('\n')[0].strip()
       if '排期' in name: continue
       g=lambda k: len(s.split('### '+k,1)[1].split('\n### ',1)[0].split('\n---',1)[0].strip('\n'))
       b=g('正文（整段复制）'); t=g('标签（整段复制）')
       print(f'{name}: 正文{b} + 标签{t} = {b+t}/800', 'OK' if b+t<=800 else '超出!')
   PY
   ```
2. **纯文本**：标了「整段复制」的段落里**不能出现任何 markdown 符号**——

   检查办法：搜 `**`、`>`、`` ` ``、`|`。只有三处例外是故意保留的：
   话题标签的 `#`、填空的 `______`、文档目录行（`#` 开头的标题，不要复制）。

### 第 9 步 · 精讲笔记 PDF（最后一步）

把这条视频讲过的表达排成一份 A4 学习资料——**只收重点词汇讲解与例句，不含旁白**。

**收什么（关键）**：**只收这条视频讲过的表达**，与视频一一对应——视频讲 12 组就排 12 组。
PDF 是视频的纸质版，不是《表达详解》的打印版：穷尽式详解（一段挖 40–60 条）是给选题库和产品练习
用的素材，整份排进 PDF 会明显比视频多出一大截。自查标准：学员把 PDF 从头看到尾，
应该刚好复习完视频里出现过的每一个表达。

**数据源**：用 `表达详解/<章节>.md`，它是**唯一真相**，不要另抄一份内容——但只取视频选中的那几条。
如果这条视频还没写表达详解（短素材直出的情况），先**按视频的讲解范围**整理成一份同格式的 md 再跑，
不要为了「补全」而写成穷尽式，那正是 PDF 与视频对不上的原因。

```bash
/opt/homebrew/bin/python3 _tools/handout.py <表达详解.md> <输出目录> \
        "<标题>" "<副标题>" [跟读练习.txt]
# 例：
#   … handout.py 表达详解/01-开场寒暄.md handout \
#     "拾句英语 · 精讲笔记 01：开场寒暄" "《On Purpose》播客开场 69 秒 · 三套话术" handout/跟读练习.txt
```

**排版**：每条 = 原句（绿）→ 意思 → 用法 → 迁移例句；带反引号的表达用等宽字高亮；
页脚放品牌与网址；末尾可加「跟读练习」。字体走系统 PingFang SC，
**无需装任何依赖**——走 Chrome 无头打印 HTML → PDF。HTML 一并留着，改 md 重跑即可。

**产出位置**：`SERIES/<选题>/<选题>_精讲笔记.pdf`（跟成片放一起）。

**原声对照（2026-09 起，可选）**：想要「整章原话的英中逐句」，就在 md 同目录放一份
`<表达详解.md 同名>.原声对照.txt`，每行 `mm:ss｜说话人｜英文原话｜中文`（`#` 开头是注释），
`handout.py` 会自动在 PDF 末尾多排一节「原声对照 · 整章逐句」——**没有这个文件就一个字不加**，
所以老选题重跑后与原来完全一致，不必逐条改脚本。原声文本取 `segments/<章节>.srt`（必要时
并回原字幕切在句中的续行），中文走**口语直译、贴近原话**，不做顺滑意译。

**校验**：① 页数；② 内嵌字体体积（有几个百 KB 的 CJK 子集，说明中文没丢字，
若字体没匹配上会变成方框、体积也不会这么大）；③ `qlmanage -t -s 1200` 出缩略图，
看墨迹占比是否在正常文字页的量级（约 2–3%）。

### 第 10 步 · 导出讲解字幕（SRT）

**每条视频都要出**，跟成片一起交付——学员拿来跟读、家长拿来核对、以后做双语版都靠它。

```bash
cd "__DATA_ROOT__/小红书发帖-拾句英语/精细讲解视频"
/opt/homebrew/bin/python3 _tools/make_srt.py <选题> [<选题> ...]
# 不给选题就跑所有「成片已存在」的选题
```

**为什么是「从成片反推」而不是直接导出旁白缓存**：

| 维度 | 做法 | 原因 |
|---|---|---|
| 文本 | 取 `SPECS` 里那张卡的**旁白原文** | 权威版本，不受 ASR 错字影响（ASR 只是拿来对时间） |
| 时间轴 | 整片转写一遍 → 按 token 对齐（中文按字、西文按词） | 缓存会被清掉，清掉之后就推不出段内时间；ASR 读的是成片本身，换音色/改文案/重渲都能重建 |
| 对齐失败 | 某卡整片对齐锚点不足（<60%）→ **把那一段剪出来单独再转一遍**，依次按「自动 / en / zh」三种识别各试一次（日志打 `~ 改段内单独转写`、`段内转写对齐成功（en/zh）`）；仍不行才按字数摊掉（打 `~ 改按字数分摊`） | 含整句英文跟读的卡，英文由中文音色念出，整片 ASR 上下文太长容易听岔；段内短上下文准得多。**中英混讲的卡，两种语言各有各的听岔处**——2026-09 实测同一条视频里两张卡分别靠 `en`、`zh` 才对上 |
| 断句 | 硬断若正好切在句末标点前，把标点归回上一条（连着几个也要一次搬完） | 否则下一条会以「。」开头、上一条没句号 |
| 过短的条 | 短于 0.5 秒的并进上一条 | 卡片末尾那条常被旁白窗口（段尾要留 0.25–3.1 秒）挤成零点几秒，一闪而过根本看不见 |
| 长空档 | 同一条卡内两条之间若是长空档（>1.2 秒），把上一条顺延到下一条前 0.1 秒（跨卡的不会顺延） | 空档基本出现在「英文原句（旁白按 0.8 倍速念）→ 中文译文」之间：ASR 对英文原句只锚到开头一小段，整句英文字幕被压成几秒，**念到一半字幕就没了**（2026-09 实测 `08` 卡 27 空了 4.8 秒） |
| 起止取法 | 起点取**首字的「起」**、结束取**末字的「止」+0.28s** | 一律取「止」的话每条都晚半个字（0.2–0.35s）才出现 |
| 卡片首条 | 首条比卡片开头晚 0.6s 以上就**拉回卡片开头**（日志会打出来） | 旁白本来就是从卡片开头念的；上一段的余音会让 ASR 把开头那句的起点听晚 0.9–1.7 秒 |
| 原声段 | **不打字幕**（只播访谈、没有旁白的那几段） | 字幕要跟旁白一一对应；原声要听懂得另配英文字幕 |
| 越界 | 每条的起止夹在本卡旁白窗口 `[a, b]` 内 | ASR 偶尔把锚点落到下一段（原声段）里，不夹的话字幕会盖到只播访谈的那几秒上 |

**校验**：① 条数与非原声段的句数大致相当；② 抽查成片开头/结尾各一条，时间点对得上画面；
③ 脚本化核对五条硬指标——**没有条落进原声段、没有越片长、没有倒序、没有非正时长、
没有短于 0.5 秒的条（也不用句末标点开头）**；
④ 日志里 `~ 改段内单独转写` 和 `~ 首条字幕偏晚` 是脚本自己处理掉的，
只有 `~ 改按字数分摊` 说明那张卡是真没对上，需人工看一眼。

```bash
/opt/homebrew/bin/python3 _tools/auto_build.py --wait 300 # 守着队列：没备好的等，备好就渲（定时任务用）
```

它做：**规格扫描 → 版面自检 → 渲染 → 成片五项校验 → 目录加序号 → 封面 → 精讲 PDF → 讲解 SRT**，
每条写成 `_tools/logs/auto_build_<时间戳>.log`。**跑之前先跑 `--dry-run`**，确认没有出界/规格不一致。

> ⚠️ **别指望 launchd 定时任务能碰这块外置盘**（2026-09 实测）：把 wrapper 放在外置盘上，
> launchd 起任务直接 `EX_CONFIG(78)`；改放本机磁盘后能启动，但脚本访问 `__DATA_ROOT__` 时
> **进程卡住（CPU 0.02s、无输出）**——是 macOS 隐私保护挡住了「可移动卷」的访问，
> 手动在终端里跑没事，因为终端早就拿到了权限。
> 要用系统定时任务，得先在「系统设置 → 隐私与安全性 → 完全磁盘访问权限」里把
> `/bin/zsh`（或对应的 Python）加进去；否则**就在有权限的终端里手动跑 auto_build**，效果一样。

### 派生版（倍速 / 试听 / 加字幕）

派生版 = 从主片 SPEC 派生一个新 SPEC，只重走 ffmpeg，**不重新调 TTS**。常用开关：

| 想要 | 写什么 |
|---|---|
| 旁白整体提速 | `speed=1.2`（段长等比缩短。`en_slow` 的 0.8 先作用，再整体乘 1.2） |
| 连访谈原声一起提速 | 再加 `speed_src=1.2`（画面同时 `setpts`，否则声画对不上、画面还会提前播完） |
| 成片落回主片目录 | `out_dir='<主片名>'`（不写就会建一个不带 `01_` 序号前缀的新文件夹） |
| 只出前 N 秒 / 挑卡 | `limit=120` 或 `cards=[c for c in ... if c['n'] in (...)]` |

**TTS 缓存要拷，别重合成**：`work` 指到独立目录时，把主片的缓存拷过去即可——
签名只跟「文本 + 音色 + 模型 + 参数」有关，跟目录无关，拷过去就是命中，不再花钱也不再调 API：

```bash
mkdir -p "_tools/work/<派生版>/elevenlabs"
cp _tools/work/<主片>/elevenlabs/*.mp3 _tools/work/<主片>/elevenlabs/*.sha256 \
   "_tools/work/<派生版>/elevenlabs/"
```

> ⚠️ **别用 ffmpeg 对成片做整体调速**（`setpts + atempo` 一把过）：成片是几十段 concat 出来的，
> 每段 AAC 都带编码补帧，重采样提速会把这些补帧算进去 —— 实测 925s 的片子会多出 6.4 秒音频，
> 而且漂移是逐段累积的，越到后面声画越不同步。要提速就走 `speed` / `speed_src` 重新出片。

### 已知坑（都踩过）

| 现象 | 原因 | 处理 |
|---|---|---|
| `PermissionError` / `hit restricted` | TRAE 沙箱只允许在**命令工作目录子树内**写文件 | `cd` 到目标目录再执行；必要时批准「在沙箱外运行」 |
| **长时后台任务写外置盘全部失败** | 后台长任务跑在更严的沙箱里，即使 `cwd` 就在目标目录、即使已批准 | 长任务（转写、批量渲染）**先写 `/tmp`**，跑完再用短命令复制。`transcribe.py` 已按此改 |
| 复制文件报 `Permission denied`，重试就好 | 沙箱偶发拦截 | **单独重试一次**，别当成路径问题 |
| 一条命令里连续写多个文件，第二个失败 | 同上 | 拆成多条命令，或失败后单独重试 |
| `Cross-device link` | 这块盘（云盘/外置卷）的 unlink 行为特殊 | `rm` 会失败；改用 DeleteFile 工具（`mv` 正常） |
| ffmpeg 写文件失败（exit 243） | **`-movflags +faststart` 在该盘写不了** | 已从脚本移除，不要加回去 |
| 画中画发虚 | 用了 640×360 的低清原片 | 换 1920×1080 高清版，并复核时间轴 |
| 成片里原声比目标句多一个词 | 从词中间切入 | 第 2 步：二次识别复核 + RMS 找静音谷 |
| 卡片文字顶到右边界 | 标题太长（62px 撑出去） | 已加标题自动缩号（62→34）；正文长行仍需自己换行 |
| SPEC 里的颜色套错样式，文字看不见 | SPEC 直接写 `GREEN`/`FG` 常量，`import` 时就被绑定到默认样式了 | SPEC 只写角色名 `'green'`/`'fg'`/`'mute'`，由 `C()` 在渲染时按当前样式解析 |
| 品牌绿块上的文字看不清 | 品牌绿 `#2DCE7B` 配浅色文字只有 1.9:1 | 品牌块上的字用 `ON_BRAND`（深色）；v2 深底上用品牌绿做强调文字是 8.1:1，可直接用 |
| 重渲旧片后风格变了 | 忘了该选题是已发布的 v1 | SPEC 里显式写 `'style': 'v1'`；回归验证：重渲一张卡与 `work/` 里的旧 PNG 比像素，应为 0 差异 |
| 改了密钥位置后渲染报 TTS 权限错 | `load_key()` 找不到 `.env.elevenlabs`，退回读 OpenMontage 里那把**无 TTS 权限**的 key | 密钥必须留在 `精细讲解视频/.env.elevenlabs` |
| **某条片子的音色/字体跟前后条不一致** | SPEC 漏写 `model`/`fonts`/`voice_settings`，回落到了旧默认（`heiti` + `eleven_multilingual_v2` + style 0） | 默认值已改成新规格；出片前跑第 3 步的「规格表扫描」；老片反过来要显式锁 `'fonts'/'model'/'voice_settings'` |
| **视频/封面被小红书限流** | 页脚曾放官网链接，被判成站外引流 | 新片连页脚一起去掉（`SHOW_FOOT` 默认 False），下半区让给正文；老片用 SPEC 的 `'foot': True` 锁原样 |
| **最后一行文字越过 1470** | 行位的 y 是**文字框顶**，墨迹还会往下延伸约 1.25×字号（44px 的行排 1410 → 墨迹到 1470） | 有原声的卡第 7 行固定排 1410，字号 ≤48px；不要排到 1425 |
| **中文末字被吞半秒、紧接着就进英文** | 掐尾滤波器的 `start_duration` 是「要看到多长的**连续有声**才停止掐」，不是「只掐超过多久的静音」。取 0.35 时它会把最后 0.4 秒语音一起削掉 | `build.py` 的 `speech()` 里用 `start_duration=0.05:start_threshold=-55dB`（实测与真实语音末尾只差 0.05 秒，那 0.05 秒本就低于 -45dB） |
| **半句之间干等两秒半** | ElevenLabs 对短分片（如单独一句 `longer term`）会返回带 2–3 秒尾部静音的 mp3，原样拼进来就是死气 | 同上：`areverse → silenceremove → areverse` 掐掉分片尾部静音，再统一 `apad` 补 0.22 秒 |
| **卡面文字被画中画盖住** | 画中画占 `(135,470)–(945,926)`；有 `source` 的卡两段都会贴画面，文字排在 490/580/800 就被压住 | 有原声的卡正文一律排 950 起（950/1030/1110/1190/1270/1350/1410）；第 4 步自检脚本已带「压画中画」判断 |
